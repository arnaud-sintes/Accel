# Glaude UI Refactoring — Execution Plan

Status: reconciled from `glaude-refactoring.md` (Opus §4 + Fable §5 addenda); Opus audit pass applied — every task carries an Agent/Effort hint, and audit findings are inlined as `**Audit note**` markers (summary under "Agent/Effort execution hints").

This plan turns the reconciled spec into an ordered, dependency-tracked task list. Each phase ships a runnable app. Backend (`Server/`, `Metrics/`, `Settings/`, `Versioning/`) stays untouched through Phase 6; `MonitorForm`/`MonitorTreeBuilder` are retired only once their replacement reaches parity (end of Phase 1/3).

## Reconciliation notes

Opus and Fable did not conflict on anything load-bearing; Opus went deeper on verified facts (native `claude.exe`, `--session-id`/`--name` flags, exact deletion set, schema, graph layout), Fable went deeper on process-lifecycle robustness and phase sequencing. Decisions locked in below are the union, with Opus's live-verified facts taking precedence wherever the two touch the same topic (e.g. Fable's phase list already assumed the hand-rolled graph and WebView2 choices that Opus separately justified).

## Locked-in architecture decisions

1. **Terminal hosting:** WebView2 + xterm.js, backed by ConPTY, transported over a new loopback WebSocket route (`Server/PtyRoutes.cs`) on the existing Kestrel `EventServer`. Hand-rolled VT parser is the fallback only if WebView2 is vetoed (weeks, not days — do not start there).
2. **`claude` invocation:** native `claude.exe` (verified: `C:\Users\a.sintes\.local\bin\claude.exe`, no shim). Resolve path fresh per launch (self-update replaces the binary in place). Re-verify with `Get-Command claude -All` on any new target machine before shipping — if it resolves to `.cmd`/`.ps1` there instead, the launch path must spawn `node.exe` + the JS entry, not ConPTY-attach the shim.
3. **Session identity/naming:** generate the session GUID in Glaude and pass `--session-id <guid> --name "<display>"` at launch — eliminates the tab↔transcript correlation race and covers naming at creation without any PTY typing. Live rename still goes through the PTY (`/rename <name>\r`), gated on `~/.claude/sessions/<pid>.json` `status == idle` before injection and confirmed by polling that file for `name`/`nameSource` to update (never screen-scrape the TUI).
4. **Session removal:** six on-disk locations (`file-history/<S>/`, `tasks/<S>/`, `session-env/<S>/`, `projects/<slug>/<S>/`, filtered rewrite of `history.jsonl`, transcript `projects/<slug>/<S>.jsonl` deleted last). Explicit do-not-touch: `shell-snapshots/*`, `paste-cache/*`, `.claude.json`. Default behavior is a recycle-bin move (`SHFileOperation`/`FOF_ALLOWUNDO`), not hard delete. Hard rule: disabled (`CanExecute=false`) while the session is running or has a live PID-registry entry; every delete target is validated as a GUID-exact leaf under `%USERPROFILE%\.claude\` with reparse points rejected before any recursive delete.
5. **Persisted metadata:** upgrade `glaude-folders.json` to a v2 schema (`{"version":2,"roots":[...],"sessions":{...}}`) switching on `JsonValueKind` so the v1 flat-array format keeps loading untouched; `RootFoldersConfig.Load` keeps its `string[]` signature so `EventServer`/`RootsRoutes`/`RootsTreeBuilder` need zero changes. `sessions` is a sparse override map (display name, pinned, hidden, last-opened) keyed by session id — never a session registry; sessions stay derived from disk. Atomic writes reuse `Settings/SettingsFile.cs`'s temp-file+backup mechanism.
6. **Panel E graph:** hand-rolled layered layout (`Orchestration`/`Layout/AgentGraphLayout.cs`, pure, unit-testable — no MSAGL, no GraphX). Data is a strict two-level star (one session root, ≤~30 sub-agent children observed), not a general graph.
7. **Process lifecycle:** one Windows Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) for the whole app; every spawned `claude` assigned immediately after `CreateProcess` (spawn-suspended → assign → resume). Graceful shutdown path (Ctrl+C → wait ~2s → `ClosePseudoConsole` + kill) runs independently of the job for normal exit, so transcripts flush and `SessionEnd` fires into the existing `EventServer`. PID registry (`glaude-sessions.json`, same tolerant-JSON/atomic-write conventions as `glaude-state.json`) stores `{sessionId, pid, processStartTimeUtc, cwd, launchedAtUtc}` for orphan reconciliation on next startup, validated against both PID and process start time (PID-reuse guard).
8. **MVVM:** one project, one process — add `<UseWPF>true</UseWPF>` alongside existing `UseWindowsForms=true` on the current `net8.0-windows` TFM (no new project). CommunityToolkit.Mvvm (`[ObservableProperty]`/`[RelayCommand]`, `WeakReferenceMessenger`). `ISessionSelectionService` is the single hub for "focused session id" — `TabsViewModel` (C) is the only writer, panels A/B/E are readers; no point-to-point panel bindings. `ITelemetryFeed` wraps the existing `SessionState.Changed` + `FileSystemWatcher` + `DebounceCoalescer` push model (unchanged 250ms debounce) rather than polling `/roots/tree` over HTTP.
9. **Visual states (panel A):** four states from `IsRunning` × `IsFocused` booleans, expressed via `DataTrigger`/`MultiDataTrigger`, glyph shape (filled/hollow) + font weight carrying state alongside color (never color-only). Model badges: letter-in-chip (`O`/`S`/`H`/`F`, `?` for unmatched), colored by family, via a new `ModelBadgeTable` mirroring `ModelWindowTable`'s prefix-match resolution. Effort: 1–4 stacked signal bars.

## Phase breakdown

### Phase 0 — Pre-flight verification

- **P0-T1**: Add `glaude doctor` verb that runs `Get-Command claude -All` equivalent (`Process.Start` + parse), reports whether `claude` resolves to a native exe, a `.cmd`/`.ps1` shim, or is missing, and fails loudly if the invocation model differs from what's assumed in P2. Files: `Cli/ArgParser.cs`, new `Cli/DoctorCommand.cs`.
  - _Agent: `general-purpose` — Effort: low._ Self-contained CLI verb next to existing `InstallCommand`/`UninstallCommand`; pattern to copy already exists, plus one xUnit case in `CliTests.cs`.
- **P0-T2**: Confirm on the actual target deployment machine(s) that WebView2 Evergreen runtime is present (or bundle the fixed-version runtime); add the check to `glaude doctor`.
  - _Agent: `general-purpose` — Effort: low._ Code part is a registry/`GetAvailableCoreWebView2BrowserVersionString` probe folded into P0-T1's command. The "confirm on target machines" half is a human/ops step the agent cannot do — it should emit the probe plus a checklist and stop, not claim verification.

### Phase 1 — WPF shell + read-only panel A

- **P1-T1**: Add `UseWPF=true` to `Glaude.csproj` alongside existing `UseWindowsForms=true` and make the app boot into WPF. **Audit note (was bundled with shell layout, split out):** `Program.cs` already owns `Main`, so an `ApplicationDefinition` (`App.xaml`) will generate a second entry point and break the build — either keep `Program.cs` as the single `[STAThread] Main` and construct `App`/`MainWindow` manually with `App.xaml` compiled as `Page`, or set `<EnableDefaultApplicationDefinition>false</EnableDefaultApplicationDefinition>`. Also verify XAML compiles under `Microsoft.NET.Sdk.Web` and survives `PublishSingleFile`.
  - _Agent: `general-purpose` — Effort: medium._ Small diff but the `Sdk.Web` + `UseWPF` + existing-`Main` + single-file combination is the one thing here that can fail in a non-obvious way; the agent must actually build and run, not just edit the csproj.
- **P1-T1b**: Scaffold `App/App.xaml`, `App/MainWindow.xaml` with the DockPanel/Grid shell (menu top, GridSplitter-separated A / center / B columns, center split C+D over E), placeholder content per panel. No behavior yet — `MonitorForm` stays reachable behind its existing verb.
  - _Agent: `general-purpose` — Effort: medium._ Pure XAML scaffolding with no interop and no tests; the only judgement calls are splitter/min-width defaults. Needs a screenshot or run-check to confirm the layout isn't collapsed.
- **P1-T2**: `Orchestration/`-adjacent `App/ViewModels/RootsPanelViewModel.cs` bound to `RootsTreeBuilder` DTOs via a new `ITelemetryFeed` service (§ locked-in decision 8) — reuse `SessionState.Changed` + `FileSystemWatcher` + `DebounceCoalescer` verbatim, marshal via `Dispatcher.BeginInvoke`.
  - _Agent: `general-purpose` — Effort: high._ The core architectural seam of the whole refactor (single push feed, no HTTP polling, no point-to-point panel bindings) plus threading correctness and expansion/selection preservation across rebuilds. Agent must read `MonitorForm.RefreshAndRender` and `MonitorTreeBuilder` first and mirror their semantics exactly.
- **P1-T3**: `glaude-folders.json` v2 schema (locked-in decision 5) — `JsonValueKind`-polymorphic loader/writer, `RootFoldersConfig.Load` keeps its `string[]` signature, atomic write via `Settings/SettingsFile.cs`, sparse `sessions` override map with prune-on-save. **Audit note (split from the root add/remove UI task):** every later phase depends on this, and it is pure, testable, non-UI work that should land as its own reviewable unit.
  - _Agent: `general-purpose` — Effort: medium._ Backend-shaped and fully unit-testable; extend `RootFoldersConfigTests.cs` with v1-still-loads, v2-round-trip, malformed→empty, and prune cases. Hard constraint for the agent: existing `RootFoldersConfig` call sites (`EventServer`, `RootsRoutes`, `RootsTreeBuilder`) must compile unchanged.
- **P1-T3b**: Root add/remove UI in panel A — add creates the directory on disk if missing and appends to `glaude-folders.json`; remove dereferences only (never deletes the folder).
  - _Agent: `general-purpose` — Effort: medium._ Depends on P1-T3. Low technical risk, but the "remove never deletes the folder" invariant is a data-safety property — state it in the task prompt and require the confirmation copy to say "stop monitoring", not "delete".
- **P1-T4**: Visual states + model/effort badge columns for panel A per locked-in decision 9 (`ModelBadgeTable`, effort bar `UserControl`, ellipsis-truncated name column, hover tooltip with session id + context size).
  - _Agent: `general-purpose` — Effort: medium._ Mechanical styling/`DataTrigger` work; `ModelBadgeTable` mirrors `ModelWindowTable`'s prefix resolution, so `ModelWindowTableTests.cs` is the test template. Never-color-only and `AutomationProperties.Name` are acceptance criteria, not suggestions.
- **P1-T4b**: **Audit note (missing task, added):** name-source ranking from addendum §4.3 — add `name_source: "ai_title"` (transcript `{"type":"ai-title",...}`, last one wins) to `RootsTreeBuilder.BuildSessionDto`, cached with the existing (length, mtime) key, and wire the full resolution order: Glaude override → live `statusLine` name → `aiTitle` → first message → truncated id. The plan otherwise never implements this, and panel A's name column is visibly worse without it.
  - _Agent: `general-purpose` — Effort: medium._ The only Phase-1 change that touches the "untouched backend" (`Metrics/RootsTreeBuilder.cs`, `TranscriptHeadReader`), so it needs care with the existing tail cache and must keep `RootsTreeRouteTests`/`TranscriptHeadReaderTests` green.
- **Exit criteria**: panel A shows live+historical sessions across all registered roots, matching `MonitorForm`'s current data fidelity, with add/remove roots working. All existing xUnit test files (23 test classes + `PlaceholderTests`) still pass unmodified — note `MonitorColumnLayoutTests.cs` is part of that set and is coupled to `MonitorForm`, so it is in scope for CX-T1, not Phase 1.

### Phase 2 — PTY terminal MVP (single session, no tabs)

- **P2-T1**: `Orchestration/ClaudeCliLocator.cs` — resolve `claude.exe` path per launch (PATH probe, cached per-launch only, per locked-in decision 2).
  - _Agent: `general-purpose` — Effort: low._ ~60 lines, pure, unit-testable with a fake PATH; the only subtlety (don't cache across launches, self-update replaces the binary) is already stated.
- **P2-T2**: `Orchestration/ConPty.cs` — P/Invoke wrapper (`CreatePseudoConsole`, `ResizePseudoConsole`, `ClosePseudoConsole`, `CreatePipe`, `InitializeProcThreadAttributeList`/`UpdateProcThreadAttribute`, `CreateProcessW` with `EXTENDED_STARTUPINFO_PRESENT`), `IDisposable`.
  - _Agent: `general-purpose` — Effort: xhigh._ Highest-risk task in the plan: raw Win32 interop where every mistake is a handle leak, a hang, or an `AccessViolation` rather than a compile error. Marshalling of `STARTUPINFOEX`/attribute lists, `SafeHandle` ownership, correct close *order* (input pipe → `ClosePseudoConsole` → handles), and `SetLastError` checks on every call are all load-bearing. Give the agent the addendum §4.2 snippet verbatim and require it to actually launch `cmd.exe` through the wrapper as a smoke check before `claude.exe`.
- **P2-T2b**: **Audit note (missing task, added):** adversarial review of the native-interop surface — `ConPty.cs`, `PtySession.cs`, and the P2-T7 Job Object interop. Checklist: every handle owned by exactly one `SafeHandle`/`finally`; no handle leaked on the failure path of a partially-constructed PTY; `CreateProcess` handle-inheritance flags minimal; attribute list freed; `Dispose` idempotent and safe from a finalizer/`ProcessExit` path; no blocking read on the UI thread; UTF-8 decoded with a stateful `System.Text.Decoder` (never per-chunk `GetString`) — risk register item 1.
  - _Agent: dedicated reviewer pass — `code-reviewer` if defined, otherwise `general-purpose` prompted read-only-then-fix and run via `/code-review --effort max` — Effort: xhigh._ Raw Win32 deserves a second, hostile pass by an agent that did not write the code. Must run the leak check empirically too (open/close 50 PTYs, compare handle count via `Get-Process -Id $PID | % HandleCount`).
- **P2-T3**: `Orchestration/PtySession.cs` — one live `claude` process + its ConPTY + byte pumps; spawn-suspended → assign to Job Object → resume (locked-in decision 7).
  - _Agent: `general-purpose` — Effort: high._ Async pump lifetime, cancellation, backpressure, `Process.Exited` reaping, and the suspend→assign→resume ordering (a race if reversed). Depends on P2-T2 and on the Job Object handle from P2-T7, so P2-T7 should be scheduled before or alongside it.
- **P2-T4**: `Server/PtyRoutes.cs` — `/pty/{tabId}` WebSocket endpoint on the existing `EventServer`, pumping bytes both ways plus a `{"resize":[cols,rows]}` control frame.
  - _Agent: `general-purpose` — Effort: high._ Mirrors `RootsRoutes`/`StateQueryRoutes` structurally (cheap), but the WebSocket close/abort handshake and binary-vs-text frame discipline are where it will misbehave. **Security requirement to put in the prompt:** the endpoint is loopback but unauthenticated and grants raw stdin to a `claude` process — require an unguessable per-tab `tabId` plus an `Origin`/token check, and add a route test that a wrong `tabId` gets 404 without side effects.
- **P2-T5**: `App/Controls/TerminalView.xaml` — WebView2 host + embedded xterm.js (+ addons) shipped as `EmbeddedResource` and served from a tiny in-process static route, no CDN/npm-at-build dependency.
  - _Agent: `general-purpose` — Effort: high._ Split from the terminal-behaviour wiring below. Bringing in the first two NuGet packages, vendoring the xterm assets (record versions + licences), `CoreWebView2` init/user-data-folder, and confirming `WebView2Loader.dll` survives single-file publish.
- **P2-T5b**: **Audit note (split from P2-T5):** terminal behaviour wiring — xterm.js ↔ `/pty/{tabId}` attach, `FitAddon` → `{"resize":[cols,rows]}` on panel resize, Ctrl+C forwarded as raw `0x03`, clipboard/bracketed paste, Cascadia Mono pinning with integer cell metrics (risk register item 4).
  - _Agent: `general-purpose` — Effort: medium._ Mostly JS glue against a working transport, but this is the task that closes the "must look like cmd.exe" risk, so acceptance is a side-by-side visual check against a real console plus the resize/emoji corpus, not a unit test.
- **P2-T6**: "Create session" popup — model/effort selection, free-text extra CLI args (e.g. `--permission-mode bypassPermissions`), generates the session GUID and launches with `--session-id <guid> --name "<display>"` (locked-in decision 3).
  - _Agent: `general-purpose` — Effort: medium._ Straightforward dialog + `ClaudeLaunchSpec` → argv construction. Two things to require: argv is built as a real argument array (never a concatenated command line, no `cmd /c`), and the free-text extra-args field is documented as trusted user input with `--dangerously-*`-style flags surfaced, not silently accepted.
- **P2-T7**: Job Object creation at app startup (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`) + PID registry (`glaude-sessions.json`) write-on-spawn/remove-on-reap, atomic writes.
  - _Agent: `general-purpose` — Effort: high._ Second block of raw Win32 (`CreateJobObject`, `SetInformationJobObject` with `JOBOBJECT_EXTENDED_LIMIT_INFORMATION`, `AssignProcessToJobObject`) plus a tolerant-JSON atomic-write file reusing `SettingsFile`'s mechanism. Registry round-trip and PID+start-time validation are unit-testable; the kill-on-close behaviour must be verified by killing Glaude from Task Manager and confirming no surviving `claude.exe`. Interop portion is covered by P2-T2b's review.
- **New tests**: PTY controller lifecycle, registry round-trip, ANSI parser/resize/emoji corpus captured from real `claude` output (risk register item 1/2).
- **Exit criteria**: single-tab interactive `claude` session running inside the WPF window, indistinguishable from cmd.exe for normal use (colors, cursor, resize, Ctrl+C). No existing tests affected.

### Phase 3 — Tabs + multi-session

- **P3-T1**: `App/ViewModels/TabsViewModel.cs` (panel C) — tab strip above D, one tab per open `PtySession`; owns `ISessionSelectionService.FocusedSessionId` writes.
  - _Agent: `general-purpose` — Effort: medium._ Ordinary MVVM. The one invariant worth asserting in the prompt: C is the *only* writer of `FocusedSessionId`, and tab close must go through `PtyRegistry`, never dispose a `PtySession` itself.
- **P3-T2**: `Orchestration/PtyRegistry.cs` — app-lifetime singleton, `tabId → PtySession`, owns disposal (not the tab ViewModels): close → `PtySession.Dispose()` → `ClosePseudoConsole` + pipe close + wait-with-timeout → `Process.Kill(entireProcessTree:true)` on timeout.
  - _Agent: `general-purpose` — Effort: high._ Concurrency-sensitive ownership code (dispose racing an exiting child, double-close, dictionary mutation during teardown) and the last line of defence against orphaned `claude` trees. Needs the N-tabs open/close stress test from this phase's test list.
- **P3-T3**: Wire `IsFocused` into panel A (highlight) and stub readers for B/E (real content lands in Phases 5/6).
  - _Agent: `general-purpose` — Effort: low._ Thin binding work on top of P1-T4's visual states and the selection service.
- **P3-T4**: App-exit graceful shutdown: dispose registry in `try/finally` around `Application.Run`, plus `SetConsoleCtrlHandler`/`AppDomain.ProcessExit` belt-and-braces. Startup reconciliation: read every `~/.claude/sessions/<pid>.json` plus `glaude-sessions.json`, treat as stale if PID dead or start-time mismatch (orphan detector), and offer "kill orphan / adopt as detached".
  - _Agent: `general-purpose` — Effort: high._ Shutdown ordering (Ctrl+C → ~2s wait → close → kill) must let `claude` flush its transcript and fire `SessionEnd` into the existing `EventServer`, so a too-eager kill silently degrades telemetry. PID-reuse guard is unit-testable; the crash path must be verified empirically. Closes risk register item 5.
- **New tests**: concurrency/reap tests (N tabs opened/closed, crash-simulated exit, orphan reconciliation on restart).
- **Exit criteria**: multiple simultaneous `claude` sessions in tabs, clean teardown on both graceful exit and simulated crash, no process leaks (verify via Task Manager / `Get-Process claude` before and after).

### Phase 4 — Session actions: rename / remove / resume / stop

- **P4-T1**: `Orchestration/SlashCommandDriver.cs` — generic `InvokeAsync(command, args, completionPredicate, timeout)`; first consumer is rename (locked-in decision 3), sanitizing input to reject `\r`, `\n`, `\x1b`, `\x03` before writing to the PTY input pipe.
  - _Agent: `general-purpose` — Effort: medium._ Small surface, but it is a *write path into the user's live agent*, so the sanitiser is a security control: allowlist-shaped, tested with a hostile-input table (embedded CR/LF, ESC sequences, `0x03`, Unicode line separators U+2028/2029, over-long names). Completion is detected by file state only — screen-scraping the TUI is banned.
- **P4-T2**: Rename UI action in panel A, gated on the `sessions/<pid>.json` status field being idle, non-modal "rename may not have applied" warning on 5s timeout. **Audit note:** the addendum only observed `status: "busy"` on disk — the exact idle value is *assumed*, not verified. Treat "not busy" as the gate, or verify the literal first and record it here.
  - _Agent: `general-purpose` — Effort: medium._ Depends on P4-T1. The gate must fail closed (unknown/missing status file → refuse injection).
- **P4-T3**: `Orchestration/SessionRemover.cs` **planner half** — build the two-phase removal plan per locked-in decision 4 (`homeDirOverride` parameter for tests, matching `RootsTreeBuilder`'s existing test pattern): enumerate the six locations, compute total bytes, and validate every target as a GUID-exact leaf under `%USERPROFILE%\.claude\` with reparse points rejected. Pure, no deletion, no I/O mutation. **Audit note (split from the executor):** planning and executing a destructive operation are two separately reviewable units, and the plan is the part that can be exhaustively unit-tested.
  - _Agent: `general-purpose` — Effort: high._ All the safety logic lives here. Tests run against a fixture `.claude` tree only — the prompt must forbid touching the real profile, and forbid the agent from running the executor at all.
- **P4-T3b**: **Audit note (split from P4-T3):** `SessionRemover` **executor half** — recycle-bin move by default (`SHFileOperation`/`FOF_ALLOWUNDO`) with a "permanently delete" opt-in, `history.jsonl` line-filter rewrite (atomic, tolerant of partial last lines), delete order with the transcript last, liveness re-check immediately before each delete, full audit log of every path acted on.
  - _Agent: `general-purpose` — Effort: xhigh._ The single most dangerous task in the plan: irreversible operations on real user data, plus more Win32 (`SHFileOperation`'s double-NUL-terminated path list is a classic marshalling footgun) and a rewrite of a *shared, concurrently appended* file. Requires the P4-T3 planner as the only source of paths — the executor must refuse any path not produced and re-validated by it.
- **P4-T3c**: **Audit note (missing task, added):** adversarial review of the destructive path — P4-T3/T3b plus the P4-T1 injection sanitiser. Checklist: can any input make a target escape `~/.claude/`; junction/symlink/hardlink and `..`/8.3-short-name/UNC/`\\?\` bypasses; case-insensitivity and Unicode-normalisation tricks in the GUID-leaf check; TOCTOU between plan and execute; `history.jsonl` rewrite losing concurrent appends or corrupting on crash mid-write; is remove truly `CanExecute=false` while running *and* while the PID registry holds a live entry; does a partial failure leave a recoverable state.
  - _Agent: dedicated reviewer pass — `code-reviewer` if defined, otherwise `general-purpose` run via `/security-review` + `/code-review --effort max` — Effort: max._ Written by an agent that did not author the code, with authority to block the phase. Closes risk register item 3.
- **P4-T4**: Resume action — `claude --resume <id>` (optionally `--fork-session`) into a new PTY/tab, same launch path as create.
  - _Agent: `general-purpose` — Effort: medium._ Mostly reuse of P2-T6's launch path; the real work is deciding tab identity for a forked session (new GUID) vs a resumed one (same GUID) so the registry and panel A don't show duplicates.
- **P4-T5**: Stop action — double-click gesture with confirmation, graceful-then-forced kill of the target `PtySession`.
  - _Agent: `general-purpose` — Effort: medium._ Reuses P3-T2/P3-T4 teardown; keep the tab open with frozen scrollback plus an exit banner rather than closing it.
- **New tests**: deletion-semantics tests against a fixture `.claude` tree (never the real profile) covering the six-location delete set and the do-not-touch list; rename-gate and sanitization tests.
- **Exit criteria**: full session CRUD from panel A working end-to-end against a real (or fixture) `.claude` profile, remove disabled while running enforced.

### Phase 5 — Panel B: file/folder tree

- **P5-T1**: `App/ViewModels/FileTreePanelViewModel.cs` — tree rooted at the focused session's `cwd` (reuse `TranscriptHeadReader`'s resolution), read-only, `FileSystemWatcher`-driven refresh.
  - _Agent: `general-purpose` — Effort: medium._ Self-contained and low-risk (read-only), but must lazy-load children and debounce/throttle the watcher — a naive eager walk of a large repo root will hang the UI thread, and one watcher per focus change must be disposed on switch. Reuse `DebounceCoalescer` rather than adding a second throttling mechanism.
- **Exit criteria**: panel B reflects the file tree of whichever session is focused via panel C, updating live while the session runs.

### Phase 6 — Panel E: agent graph

- **P6-T1**: `Orchestration/Layout/AgentGraphLayout.cs` — pure function, `AgentGraphModel → AgentGraphLayoutResult` (node rects + edge segments), unit-tested with no UI (locked-in decision 6). Root centered top, children row-wrapped past ~8, cubic-Bézier edges.
  - _Agent: `general-purpose` — Effort: medium._ Ideal isolated sub-agent task: pure function, no WPF references, fully unit-testable (deterministic rects, wrap boundary, empty/one-child/30-child cases). Sits beside `MonitorColumnLayout` as precedent.
- **P6-T2**: `App/ViewModels/AgentGraphViewModel.cs` + `Canvas`/`ItemsControl` rendering, node `DataTemplate` showing model badge, effort, context-window gauge, tokens, elapsed time — bound to the same `AgentRecord`/`SessionSnapshot` data `RootsTreeBuilder` already produces.
  - _Agent: `general-purpose` — Effort: medium._ Depends on P6-T1 and reuses P1-T4's badge controls. Watch for churn: the graph rebuilds on every 250ms telemetry tick, so diff/update the node collection instead of clearing it, or the panel will flicker.
- **Exit criteria**: graph panel shows the focused session as root with live sub-agent children, matching data already visible in panel A's tree today, just re-rendered as a graph.

### Phase 7 — Panel B: git capabilities

- **P7-T1**: Status badges via `git status --porcelain=v2` shelled out per refresh (no `libgit2sharp` dependency initially) — deferred/optional per original requirement ("later augmented with git capabilities").
  - _Agent: `general-purpose` — Effort: medium._ Parsing `porcelain=v2` correctly (`1`/`2`/`u`/`?` record types, rename entries, NUL-vs-newline separators) is the substance and is unit-testable from captured fixture output; reuse `ShellCommandRunner` rather than a fresh `Process.Start`. Must be non-blocking and no-op outside a repo.
- **Exit criteria**: modified/untracked/staged indicators on panel B's tree nodes.

Drop `UseWindowsForms` from the csproj only after confirming nothing else in `Cli/` references WinForms.
